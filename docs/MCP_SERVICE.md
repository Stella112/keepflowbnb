# First Bell MCP service — 2026-10-09

The existing strict tool dispatcher in lib/tools/service.ts and production bindings in lib/tools/application.ts are preserved. The new POST /api/mcp endpoint wraps those handlers with the official @modelcontextprotocol/sdk 1.32.1 Streamable HTTP transport. It uses stateless JSON responses and exposes 22 discovery, private read, unsaved draft and read-only preparation tools. GET and DELETE return 405 because no SSE or protocol session is maintained.

Public tools include stock discovery/factual research, Bell definitions/history/comparison and unsaved allocation drafts. Private tools include paper portfolio/drift, receipts, recorded decisions, personal-policy drafts, contribution/rebalance previews and owned execution status. Tool portfolio values remain explicitly PAPER; actual-wallet contribution planning is a separate /api/wallet/plan boundary. Factual Binance briefs do not claim paid analyst or Agent Studio research.

Preparation tools bind actual wallet balance, quote/build/simulation checks. They can persist private dry-check evidence and therefore do not advertise the MCP readOnlyHint annotation. They grant no signing, spending or execution authority. Stock inputs remain capped at 25 USDT, Bell check inputs at 100 USDT. All results state executionAvailable:false. No raw signing or arbitrary approval payload is exposed.

Bell mutation tools and request_bell_execution are not listed or callable through this transport. Existing confirmed owned Bell operations retain their separate application boundaries. The dispatcher continues to enforce strict schemas, scoped identity, ownership and version CAS wherever applicable.

Every HTTP request requires a secure same-origin First Bell request (HTTPS or exact localhost preview). Private calls derive a verified, unexpired, unrevoked opaque wallet session and the required PRIVATE_READ or EXECUTION_PREPARATION scope on every call. MCP session IDs, user-supplied identity, authorization fields and wallet addresses grant no authority. A protocol client does not gain wallet access merely by connecting. Tests use only synthetic unfunded signers and their own test sessions; no user credential is distributed to external assistants.

SDK parsing caps requests at 8192 bytes. HTTP admission and each allowed tool call consume the bounded preview quota; batching cannot multiply provider operations for one slot. Errors are sanitized, responses are noncacheable, and protocol handlers close after JSON response completion. Four official SDK client tests cover initialization/discovery, existing tool dispatch, revoked identity on an open client, strict input/context rejection, origin/body limits, delayed handler completion and batch quota enforcement. Independent review found and repaired the batch bypass and preparation annotations.

Audit found no older MCP SDK/transport in the available workspace or searched local roots. This implementation extends the existing First Bell handlers; it does not discard any source. If a separate original repository is supplied later, it must be audited and reconciled. Scoped manual bearer read grants are implemented and publicly verified; automatic OAuth and real financial execution remain unimplemented.

Deployed protocol acceptance: test-results/mcp-protocol-proof.json reports PASS using the official SDK client, synthetic unfunded wallet sessions and the production endpoint through encrypted SSH. Verified discovery, existing Bell read, private paper portfolio, strict input and foreign-origin rejection, and revocation on an already-open client. No external assistant grant or financial execution occurred.

get_stock_underlying accepts only curated ticker and issuer (ondo/bstock); its backend resolves the exact current BSC contract and independently validates company/profile and market responses. It is public read-only and available as an explicitly selectable manual grant scope. Missing endpoint/metric data remains unavailable/null, never invented.

## 2026-10-11: purchase review links, wallet-scoped previews, Flow names

Live audit (official SDK client 1.32.1, anonymous, against https://keepflow.site/api/mcp, 01:48 UTC): 9 public tools discovered; search_stock, get_stock, get_bell and get_stock_research returned live Binance data in 450–1015 ms; an invalid ticker and private/preparation calls were refused. Defect found: create_bell_from_prompt("$50 in AI chip stocks...") returned only "could not be verified" because the parser's guidance used curly quotes the error filter rejected. Fixed: guidance now lists the available tickers, the filter accepts typographic quotes, and schema errors name the failing field.

Added (code, tested locally and on the VPS; live after the next deploy):
- prepare_purchase_review: 15-minute link to /review/<24-char random id>. The link stores only ticker/issuer or Flow id+version and amount. The page uses the existing wallet-signed purchase panels, which sign the user in, re-quote, check balance and rules and simulate before the wallet asks. Links made with a grant are bound to that account. Calling the tool executes nothing.
- quote_flow, simulate_flow_buy and Flow-named aliases get_flow, get_flow_versions, compare_flow_versions, create_flow_from_prompt and modify_flow_from_prompt. All *_bell names still work.
- quote_stock and quote_flow without wallet scope return kind INDICATIVE_ESTIMATE (live RWA token price, executable:false). Binance documents userWalletAddress as required for tokenized-stock quotes, so no executable quote is claimed without a wallet.
- Assistant grants may now include quote_stock, quote_flow, simulate_stock_buy, simulate_flow_buy, prepare_purchase_review and get_wallet_portfolio. They run for the grant's verified, account-linked wallet (channel ASSISTANT_GRANT). prepare_bell_execution and request_bell_execution remain website-only or disabled. A token still lists and calls only its granted tools, re-checked on every call.
- get_wallet_portfolio: real BSC balances of the verified wallet (get_portfolio stays paper).
- KEEPFLOW_* environment names alias FIRSTBELL_* (old names win if both are set). Token prefix fbm_ and cookie names are unchanged so existing clients and sessions keep working.

Not implemented: Agentic Wallet execution through MCP (Autopilot uses each user's own connected Agentic Wallet on the website only), OAuth for claude.ai connectors (they can't send custom headers, so they get public tools only).
